# Hand tracker

Mobile web app (Vite + TypeScript, MediaPipe Tasks Vision `HandLandmarker` in a worker, Three.js): live 3D hand tracking, fingers from the wrist up, from one phone camera held close (about 20–80 cm, bare hands), with rigged 3D hands and a box to push and pinch-grab. The goals are accurate tracking and speed. It started as a shadow-boxing body tracker (repo name `boxxing`); the boxing niche and full-body tracking were dropped on purpose and the code deleted (still in git history before `57195e0`).

## Run, test, deploy

- Node 22.12+. `npm ci`, `npm run assets` (hand model from storage.googleapis.com + WASM into `public/`, git-ignored except `public/models/manifest.json`), `npm run dev`, `npm test`, `npm run build`.
- Browser check: `BASE_PATH=/boxxing/ npm run build && node scripts/check-ui.mjs [outDir]`. Uses the global Playwright and Chromium's fake camera; checks portrait/landscape `?demo=1`, no scrolling, nothing extra, no console errors, 3D hands move, mirror, and that the camera path loads the model.
- Deploy: push to `main` → `.github/workflows/pages.yml` builds with `BASE_PATH=/<repo>/` and publishes `dist/` to https://boxxing-app.github.io/boxxing/. The repo lives in the `boxxing-app` organization because the owner's personal `github.io` redirects to an unrelated custom domain.

## Files

- `main.ts` the screen; `style.css`; `config.ts` URL parameters; `hands.ts` geometry (focal length, pinhole position solve, fixed finger lengths, handedness); `viewer.ts` 3D scene; `handmodel.ts` rigged hand posed from landmarks; `physics.ts` box, table, push and pinch-grab; `sensors.ts` phone tilt; `public/hands/*.glb` WebXR generic hands (MIT); `demo.ts` synthetic hands for tests and `?demo=1`; `filter.ts` One Euro; `math.ts`.
- `tracker.ts`, `hand.worker.ts`, `asset-loader.ts`, `camera-access.ts`, `wasm-bootstrap.ts`: camera + model loading. Where Chrome has `MediaStreamTrackProcessor`, the camera track's frames stream straight into the worker (newest frame only, no copy on the page thread); if the first frame's size or rotation differs from the `<video>`, it falls back to `createImageBitmap` per frame. MediaPipe timestamps use the worker's clock on both paths.

## Decisions (keep unless the user changes them)

- One screen, two views, nothing else but one quiet status line (loading, errors, FPS, each hand's distance in cm).
- 3D view: a fixed isometric view (orthographic camera, 35° down, 45° to the side, 0.6 m tall) of the level scene, from above and behind your hands (front camera) or behind the phone (rear camera), so your right hand is on the right with no mirroring. It does not move with the phone, does not orbit, and does not line up with the camera image. Soft shadows under the hands and the box show height. Double-tap re-places the table (under your hands) and box and re-measures the fingers. Landscape = camera left, 3D right; portrait = camera top, 3D below. Settings only through URL parameters (`camera=rear`, `res`, `fov`, `minCutoff`/`beta`/`dCutoff`, `debug=1`, `demo=1`).
- Camera: default `1280x960` (4:3 = whole sensor; 16:9 crops it) with `resizeMode: none`, and zoom set to its minimum where exposed. The rear camera prefers a lens labelled wide/0.5.
- Front camera: mirror the camera image only (CSS `scaleX(-1)`); never flip data. The 3D view is never mirrored. Rear camera is not mirrored.
- Hands: the WebXR generic hand (25 joints, all direct children of the armature) is posed by setting each joint on its landmark (finger metacarpals: rigid offset from the wrist), turning it with the palm frame (wrist, index/middle/pinky knuckles) and aiming it exactly at the next joint; bones scale with hand size. Lambert materials. An instanced skeleton shows until the models load.
- Box: 6 cm cube on a 60×56 cm level table. The table shows from the start (below where hands usually are) and moves once hands have been in view for 0.3 s: centred under the palms, its top 12 cm below them but never higher than 6 cm below the camera, facing the camera's heading (`tablePose`); double-tap (or the first tilt reading) re-places it. Placing it along the camera's view instead put it above the camera whenever the phone leaned back, so the view looked up at its underside. Hands are kinematic spheres (joints + bone midpoints, 1.1 cm); pinch = thumb–index tips < 2.5 cm (release > 4 cm) within 3 cm of the box; release throws with the hand's speed; it settles flat; off the table it respawns. Physics runs in the 60 Hz draw loop on the blended hand poses.
- Speed: no MSAA, Lambert materials, render only when something changed, pixel ratio adapts between 0.75 and 1.5 to keep frames under ~22 ms.
- Handedness: MediaPipe labels hands as if the image were mirrored; frames are never mirrored, so `sideOf()` swaps the label. If both hands get the same label, the less certain one becomes the other side. Right = green, left = blue.
- Position: each hand's origin is placed by an exact linear pinhole solve of its 3D world landmarks against its image points (`solveTranslation`), with f from `?fov` (default 70° across the long side). `fov` only scales depth.
- Shape: fixed bone lengths per hand = median of the first 30 frames; each bone aimed exactly along its landmark direction, built out from the wrist (`HandShape`). Double-tap re-measures.
- Smoothing: hand shape (metres, relative to the hand centre) minCutoff 1, beta 5, dCutoff 2, per hand; position has its own steadier filter (1, 2, 1). Position is solved from the palm points only (`PALM`: wrist + knuckles), which are steadier than fingertips.
- Display: the 3D view draws slightly in the past (smoothed tracker delay + one frame interval) and blends between the two tracker results around that time (`sampleAt`), so motion is smooth at 60 Hz even when tracking runs at 20–30 Hz. A lost hand is held for 250 ms. Joints and bones are instanced (a few draw calls per hand).
- Sides: `trackSides` keeps each hand on its side by wrist position while it was seen in the last 300 ms; labels only decide new hands.
- Phone sensors (`sensors.ts`): gravity from Chrome's `GravitySensor`, else `deviceorientation` (iOS asks on the first tap), levels the 3D view and grid. Only tilt is used: phone position from the accelerometer drifts, and no web API exposes a depth sensor or the hand's distance, so distance comes from the pinhole solve. URL smoothing is stored under `hands.smoothing.v1`; older keys are deleted.
- Privacy: no backend, no analytics, no uploads. The worker blocks external fetch/XHR; CSP `connect-src 'self'` lives in `index.html` (GitHub Pages ignores `public/_headers`). Every runtime URL uses Vite's `BASE_URL` (the site lives under `/boxxing/`).
- `V(p)=(x,-y,-z)` converts MediaPipe camera axes (x right, y down, z forward) to Three.js.
